Resumo executivo

Este trabalho realizou o pré-processamento de três bases de crédito: emprestimos.csv, serasa.csv e emprestimos_anteriores.csv. A base de empréstimos foi tratada como base principal, pois contém a variável alvo TARGET e uma linha por cliente da amostra. As outras duas bases foram agregadas por SK_ID_CURR antes da junção, evitando duplicidade de clientes.

O resultado foi uma base final limpa, sem valores ausentes, com variáveis demográficas selecionadas, campos financeiros, agregações de histórico externo e interno, variáveis categóricas codificadas e uma métrica de risco calculada em uma cópia de trabalho.

307.511 registros preservados da base principal
41 colunas na base final preprocessada
43 colunas na base final com métrica
0 valores ausentes após o tratamento final
Ideia central: o objetivo não foi treinar um modelo, mas preparar uma base robusta, rastreável e reprodutível para uma futura etapa de Machine Learning.

1. Introdução

O pré-processamento é uma etapa essencial em projetos de Ciência de Dados. Antes de aplicar algoritmos de Machine Learning, é necessário compreender a origem dos dados, selecionar variáveis relevantes, integrar fontes diferentes, tratar inconsistências, lidar com valores ausentes e documentar as transformações realizadas.

Neste projeto, o cenário analisado é a concessão de crédito. A variável de interesse é o comportamento do cliente em relação ao pagamento. O campo TARGET assume valor 0 para clientes saudáveis, sem dificuldade de pagamento, e valor 1 para clientes de risco, com dificuldade ou atraso.

A estratégia adotada foi manter a base emprestimos.csv como base âncora e enriquecer cada cliente com informações resumidas do histórico externo e do histórico interno. Todas as etapas foram implementadas em Python com pandas e SQLite, e os resultados foram salvos em CSV, JSON e banco de dados.

2. Descrição das bases de dados

As três bases possuem granularidades diferentes. A base principal tem uma linha por solicitação da amostra. Já as bases Serasa e empréstimos anteriores podem ter múltiplas linhas para o mesmo cliente, exigindo agregações antes da junção.

Arquivo Descrição Registros Granularidade
emprestimos.csv Base principal com dados demográficos, financeiros e variável alvo. 307.511 Uma linha por cliente/solicitação da amostra.
serasa.csv Histórico externo do cliente em outras instituições financeiras. 1.716.428 Várias linhas por cliente, uma para cada crédito anterior no bureau.
emprestimos_anteriores.csv Histórico interno de solicitações anteriores na própria instituição. 1.670.214 Várias linhas por cliente, uma para cada solicitação anterior.

2.1 Base Empréstimos

A base emprestimos.csv foi usada como referência central do projeto. Dela foram preservados a chave SK_ID_CURR, a variável alvo TARGET, variáveis financeiras como renda e valor de crédito, além de dados demográficos e sociais selecionados.

2.2 Base Serasa

A base serasa.csv contém créditos anteriores reportados ao bureau. Como o mesmo cliente pode ter vários créditos registrados, a base não deve ser unida diretamente à base principal. Primeiro ela foi resumida por SK_ID_CURR.

2.3 Base Empréstimos anteriores

A base emprestimos_anteriores.csv representa o histórico interno de solicitações anteriores. Ela permite avaliar se o cliente já tentou crédito na instituição, se já foi recusado, se pediu seguro e qual foi a diferença entre o valor solicitado e o valor aprovado.

3. Seleção e justificativa das variáveis

A seleção de variáveis seguiu o enunciado e buscou manter atributos relevantes para análise de risco. Foram usados todos os campos obrigatórios da base de empréstimos e mais de três campos opcionais, ampliando a capacidade descritiva da base final.

5. Construção da base final

A base final foi construída com a base de empréstimos como âncora. As bases Serasa e empréstimos anteriores foram agregadas separadamente e, em seguida, unidas à base principal por meio de junções à esquerda (left join). Essa decisão preservou todos os 307.511 registros da base principal.

  1. Leitura dos campos selecionados da base emprestimos.csv.
  2. Agregação da base serasa.csv por SK_ID_CURR.
  3. Agregação da base emprestimos_anteriores.csv por SK_ID_CURR.
  4. Junção das bases agregadas com a base principal.
  5. Criação de AGE_YEARS e CREDIT_INCOME_RATIO.
  6. Tratamento de valores ausentes.
  7. Codificação das variáveis categóricas.
  8. Exportação da base final e da base com métrica.
  9. Criação do banco SQLite com a tabela base_final_metrica.

Estrutura final

Grupo Campos Tratamento
Identificação SK_ID_CURR Chave primária mantida na base final.
Alvo TARGET Variável alvo preservada sem alteração.
Demográficas e financeiras Renda, crédito, idade, filhos, região, contatos e scores externos. Seleção direta, transformação de idade, razão crédito/renda e imputação pela mediana quando necessário.
Categóricas Gênero, carro, imóvel, escolaridade, renda, moradia, ocupação e organização. Preenchimento com Unknown e codificação em números com dicionário.

6. Tratamentos aplicados e desbalanceamento

O tratamento foi feito com regras simples e justificáveis, adequadas ao objetivo de pré-processamento. A base final ficou sem valores ausentes, com categorias codificadas e com dicionário de mapeamento salvo.

Problema Solução aplicada Motivo
Cliente sem histórico Serasa ou interno Campos agregados preenchidos com zero. Ausência de registro foi interpretada como ausência de evento anterior.
Ausentes numéricos da base principal Imputação pela mediana. A mediana é menos sensível a outliers do que a média.
Ausentes categóricos Categoria Unknown. Preserva a informação de ausência como uma categoria própria.
Texto em variáveis categóricas Codificação numérica e dicionário de categorias. Permite uso em modelos e mantém rastreabilidade.

Distribuição da variável alvo

A variável TARGET apresentou forte desbalanceamento. A classe saudável é dominante, enquanto a classe de risco representa uma parcela menor da base.

TARGET 0 - Saudável
282.686 (91,93%)
TARGET 1 - Risco
24.825 (8,07%)
Cuidado metodológico: a base final não foi balanceada artificialmente, pois o objetivo desta entrega é pré-processamento e documentação. Em uma etapa futura de modelagem, técnicas de balanceamento devem ser aplicadas somente no conjunto de treino, para evitar vazamento de informação.

7. Métrica customizada de risco

Foi criada uma métrica de risco de 0 a 100 em uma cópia da base final, preservando a base preprocessada original. A métrica combina 10 campos finais, com normalização robusta e pesos definidos manualmente.

A normalização robusta usa os percentis 1% e 99%, reduzindo a influência de valores extremos. Campos em que valores maiores indicam menor risco, como renda e scores externos, tiveram a escala invertida.

Avaliação complementar com estatística de Hopkins

Como verificação adicional, foi calculada a estatística de Hopkins sobre uma amostra da base final usando os 10 campos da métrica. Essa estatística mede se os dados apresentam tendência de agrupamento, comparando a distribuição dos pontos reais com pontos artificiais gerados aleatoriamente.

Métrica Valor obtido Interpretação

A estatística de Hopkins era opcional no enunciado. Ela foi incluída como melhoria adicional para reforçar a análise de qualidade da base final.
